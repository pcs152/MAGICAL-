# 2026-05-30 寄生解释知识库 v0.1

## 1. 这个知识库解决什么问题

Magic / MAGICAL 已经能输出 PEX 结果，但 PEX 本身只回答“版图中有哪些寄生电容/电阻”。覃林峰方向要继续回答的是：

```text
这些寄生集中在哪些网络？
它们可能影响哪些性能？
性能下降更像是前端设计余量不足，还是后端布局布线造成？
Harness 下一步应该回前端、回参数优化、回后端，还是要求人工检查？
```

所以本知识库不是替代 Magic PEX 工具，而是把 PEX 结果转成“可解释、可决策、可复用”的工程规则。

### 2.3 专业知识与论文

论文和教材不直接变成 Harness 规则。它们的作用是解释“为什么这个规则合理”，例如：

```text
高阻节点额外电容 -> 极点下移 -> 带宽或相位裕度变化
输出节点额外电容 -> 负载变重 -> 速度/带宽/驱动能力变化
差分两侧寄生不对称 -> 失配风险 -> offset / CMRR / PSRR 可能受影响
敏感节点与大摆幅节点强耦合 -> 信号串扰 -> 噪声或稳定性风险
```

## 3. 每条规则的标准格式

后续每条规则都按下面格式写，避免变成散乱笔记：

```text
规则名称：
触发条件：
可能含义：
优先检查：
建议动作：
证据字段：
适用范围：
已验证 case：
资料依据：
置信度：
```

其中 `置信度` 分为：

```text
低：来自经验判断，还没有本项目 case 证明
中：本项目至少一个 case 观察到相关现象，但还缺后仿闭环
高：已有 PEX + 前后仿差异 + 修改后改善的闭环证据
```

## 4. 首批规则

### 4.1 输出节点寄生电容过大

规则名称：输出节点负载过重。

触发条件：

```text
输出节点 C_total 排名前 3
并且后仿带宽、速度、压摆率或输出摆幅明显下降
```

可能含义：

输出节点被版图连线、电源耦合或后级负载拖重，等效负载电容变大。

优先检查：

```text
输出线是否过长
输出线是否与电源/地/大摆幅线长距离并行
输出是否经过不必要的绕线
输出驱动管尺寸和偏置电流是否太弱
```

建议动作：

```text
优先回后端：缩短输出线、换更高层金属、增加线宽、减少并行耦合
若后端已经很干净：回前端 sizing，提高驱动或调整补偿
```

证据字段：

```text
parasitic_summary.total_cap_by_net[output]
parasitic_summary.top_caps
postlayout_metrics.bandwidth / slew / gain
prelayout_metrics 与 postlayout_metrics 的退化比例
```

适用范围：放大器输出、比较器输出、反相器输出、缓冲器输出。

已验证 case：`inverter_core_post_cleanup` 中 `Y` 为输出候选节点，当前 `Y` 连接电容约 1.25472 fF。还缺后仿差异闭环。

资料依据：基础 RC 负载模型；Magic PEX summary；OpenRCX 对 ground / coupling capacitance 的结构化定义。

置信度：中。

### 4.2 高阻节点寄生电容过大

规则名称：高阻敏感节点被寄生拉低极点。

触发条件：

```text
某内部节点 C_total 较大
该节点属于高阻节点、增益节点、补偿节点或电流镜节点
后仿带宽、相位裕度、增益或稳定性变差
```

可能含义：

高阻节点本来电阻大，额外寄生电容会显著改变该点时间常数，容易移动极点。

优先检查：

```text
该节点是否是一级输出、二级输入、补偿节点或电流镜输出
该节点是否有长线
该节点是否靠近电源线、输出线或大摆幅线
该节点是否有不必要的跨区域连接
```

建议动作：

```text
后端：让高阻节点更短、更安静、远离大摆幅线，必要时加屏蔽
前端：调整补偿、电流或器件尺寸，降低对该节点寄生的敏感度
```

证据字段：

```text
critical_nets.role == high_impedance
total_cap_by_net[net]
postlayout_metrics.phase_margin / bandwidth / gain
```

适用范围：OTA、运放、电流镜、偏置网络。

已验证 case：`ota_core` 中 `a_25_264#` 和 `a_425_364#` 是匿名内部节点，连接电容较高，后续需要给它们补语义标签。

资料依据：模拟电路极点/零点基础；Magic PEX summary。

置信度：低到中。

### 4.3 差分输入两侧寄生不对称

规则名称：差分对寄生失配。

触发条件：

```text
VINP 与 VINM 的 C_total 差异超过阈值
或 VINP/VINM 与其他节点的耦合对象明显不对称
```

可能含义：

差分输入两侧版图不对称，可能引入 offset、CMRR 下降或差分响应不平衡。

优先检查：

```text
差分输入线长度是否接近
耦合到电源/地/输出/内部节点的电容是否接近
器件摆放是否镜像或共心
pin 位置是否导致一侧绕线更长
```

建议动作：

```text
优先回后端：补 matching / symmetry 约束，调整 pin、布线、器件映射
若结构本身不对称：回前端重新标注差分语义或调整拓扑
```

证据字段：

```text
cap_by_net[VINP]
cap_by_net[VINM]
coupling_pairs involving VINP / VINM
matching_delta = abs(C_VINP - C_VINM) / max(C_VINP, C_VINM)
```

适用范围：差分输入 OTA、比较器、差分放大器。

已验证 case：`ota_core` 中 `VINP` 约 0.460555 fF，`VINM` 约 0.462086 fF，当前输入总电容非常接近，这是一个“好样例”。

资料依据：差分对匹配常识；本项目 `ota_core` PEX 结果。

置信度：中。

### 4.4 电源/地寄生占比很高

规则名称：电源网络寄生主导。

触发条件：

```text
VDD/GND 或 VPWR/VGND 的连接电容显著高于信号节点
且后仿出现供电噪声、功耗异常、工作点漂移或动态响应异常
```

可能含义：

电源地网络面积大、耦合多，本身高电容不一定是坏事；但如果电源地与敏感节点耦合强，可能影响偏置或动态性能。

优先检查：

```text
最大电容是否只是 VDD-GND 去耦类耦合
信号节点是否强耦合到电源/地
偏置节点是否强耦合到电源/地
电源地路径是否造成额外压降或连接异常
```

建议动作：

```text
不要因为 VDD/GND 排名高就直接判失败
先看信号节点与电源/地的耦合占比
必要时回后端调整电源地布局、屏蔽和敏感节点间距
```

证据字段：

```text
top_caps involving VDD/GND
signal_to_supply_coupling_ratio
postlayout_metrics.operating_point / power
```

适用范围：所有模拟版图。

已验证 case：`ota_core` 中 `VDD-GND` 最大电容约 4.01869 fF，因此需要把“电源地大电容”和“危险信号寄生”分开解释。

资料依据：Magic PEX summary；OpenRCX ground/coupling capacitance 概念。

置信度：中。

### 4.5 敏感节点与大摆幅节点耦合

规则名称：敏感网被大摆幅网串扰。

触发条件：

```text
top coupling pair 中同时出现 sensitive_net 与 large_swing_net
后仿噪声、相位裕度、瞬态波形或 settling 变差
```

可能含义：

大摆幅节点通过耦合电容向敏感节点注入扰动。

优先检查：

```text
输出线是否贴近输入线、偏置线或高阻内部节点
是否存在长距离平行布线
是否缺少屏蔽线或层分离
```

建议动作：

```text
优先回后端：层分离、加屏蔽、改变走线方向、减少并行长度
必要时回前端：提高敏感节点驱动、调整补偿或引入缓冲
```

证据字段：

```text
coupling_pairs
net_roles.sensitive
net_roles.large_swing
postlayout_metrics.noise / settling / phase_margin
```

适用范围：OTA、运放、比较器、采样电路。

已验证 case：暂无，需要从后续后仿差异中补。

资料依据：耦合电容基本模型；OpenRCX coupling capacitance 说明。

置信度：低。

### 4.6 PEX 不大但后仿崩溃

规则名称：退化不应只怪寄生。

触发条件：

```text
关键网络寄生不突出
但后仿性能大幅恶化
```

可能含义：

问题可能来自仿真 setup、模型角落、端口映射、器件参数、LVS 语义、工作点或前端设计本身，而不是单纯的线寄生。

优先检查：

```text
前后仿 testbench 是否一致
电源地和输入输出端口是否一致
LVS 是否真的 match
后仿网表是否包含正确器件模型
工作点是否漂移
```

建议动作：

```text
Harness 标记为人工检查或仿真配置检查
不要直接回后端乱改版图
若工作点漂移明显，再回参数优化或偏置设计
```

证据字段：

```text
parasitic_summary.total_cap_ff
lvs_result.match
prelayout_metrics.operating_point
postlayout_metrics.operating_point
simulation_config_diff
```

适用范围：所有 case。

已验证 case：暂无。

资料依据：后仿 debug 常识；本项目后续需要补 case。

置信度：低。

## 5. 当前两个 case 的初步解读

### 5.1 `inverter_core_post_cleanup`

已知事实：

```text
DRC_COUNT = 0
CONNECTIVITY_LVS_MATCH = yes
PEX_CAPS = 6
PEX_TOTAL_CAP_FF = 4.16931 fF
Y 节点连接电容约 1.25472 fF
A 节点连接电容约 1.39887 fF
```

初步解释：

```text
这是一个适合验证 parasitic_summary.json 格式的小 case。
它的网络少，适合检查 total_cap_by_net、top_caps、输入/输出节点标注是否正确。
它暂时不能证明“寄生导致性能下降”，因为还缺前仿/后仿指标差异。
```

### 5.2 `ota_core`

已知事实：

```text
DRC_COUNT = 0
CONNECTIVITY_LVS_MATCH = yes
PEX_CAPS = 25
PEX_TOTAL_CAP_FF = 8.31439 fF
VINP 约 0.460555 fF
VINM 约 0.462086 fF
VOUT 约 0.571317 fF
匿名内部节点 a_25_264# 约 1.93934 fF
匿名内部节点 a_425_364# 约 1.46532 fF
```

初步解释：

```text
VINP / VINM 寄生接近，说明它可以作为差分输入寄生对称性的正例。
匿名内部节点寄生较高，但缺少电路语义，下一步需要把匿名节点映射成可解释节点。
VDD / GND 电容最大，但不能简单判定为危险，需要看它们是否强耦合到敏感信号节点。
```

## 6. 下一步最小实现

### 6.1 `parasitic_summary.json`

优先让脚本输出这些字段：

```json
{
  "case_name": "ota_core",
  "top_cell": "ota_core",
  "total_cap_ff": 8.31439,
  "capacitor_count": 25,
  "cap_by_net": {
    "VINP": 0.460555,
    "VINM": 0.462086,
    "VOUT": 0.571317
  },
  "top_caps": [],
  "net_roles": {
    "VINP": "differential_input_plus",
    "VINM": "differential_input_minus",
    "VOUT": "output",
    "VDD": "power",
    "GND": "ground"
  },
  "rule_hits": []
}
```

### 6.2 `rule_hits`

首批只做 3 个自动规则：

```text
输出节点电容排名
差分输入电容不对称度
信号节点到电源/地的耦合占比
```

### 6.3 和 Harness 的接口

寄生模块不直接决定最终成败，只输出诊断建议：

```text
pass_observation：寄生正常，继续后仿/交付检查
backend_review：更像版图问题，回布局布线或约束
frontend_review：更像前端敏感，回 sizing / 补偿 / 拓扑
manual_check：证据不足，需要人工检查仿真或节点语义
```

## 8. 这份 v0.1 的边界

这份文档现在只做到：

```text
把 PEX 结果解释为工程诊断问题
建立规则模板
```
