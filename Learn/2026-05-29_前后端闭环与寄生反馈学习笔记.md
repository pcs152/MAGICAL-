# 2026-05-29 前后端闭环与寄生反馈学习笔记

## 1. 今天学到的核心结论

模拟 IC 自动化设计不能只理解成“前端给网表，后端生成版图”。更准确的理解是：

```text
用户需求
-> 前端拓扑与网表生成
-> 参数优化与前仿
-> MAGICAL 候选版图生成
-> DRC / LVS / PEX
-> 后版图仿真
-> Harness 失败归因
-> 回到前端或后端修正
-> 最终 GDS 交付
```

其中，`MAGICAL` 生成的是候选版图，不应直接称为最终 GDS。最终 GDS 应该是通过 DRC、LVS、PEX 和后版图性能验证后的交付版图。

## 2. Harness 的本质

Harness 不是普通脚本调度器。它真正要做的是：

- 约束检查：每一步是否满足指标、工艺和规则。
- 流程调度：决定下一步跑什么。
- 失败归因：判断问题来自前端、后端、寄生，还是器件映射。
- 回退决策：决定失败后回到哪里修。

所以 Harness 的关键不是“能不能跑流程”，而是有没有一套可量化的“度”。

这个“度”至少包括：

- 前仿性能：前版图仿真的 gain、bandwidth、phase margin、power、operating point。
- 后仿性能：带寄生网表仿真后的同类指标。
- 寄生指标：总寄生电容、单网络电容、关键网络、最大寄生电容。
- 退化指标：前仿到后仿的性能下降比例。

例如：

```text
目标带宽 = 100 MHz
前仿带宽 = 150 MHz
后仿带宽 = 105 MHz
退化比例 = (150 - 105) / 150 = 30%
```

这种设计虽然最终过线，但 Harness 仍然应该记录“性能通过但后仿退化较大”，而不是简单判断为通过。

## 3. 为什么不能只让前端多留余量

一个直觉是：如果目标是 100，那前端 sizing 时直接做到 150，后端掉一点也能过。

这个想法有道理，本质上是设计裕量或 guard band。但它不能无脑使用，因为裕量不是免费的。

提高前端性能通常会带来代价：

- 功耗增加。
- 面积增加。
- 晶体管尺寸变大。
- 寄生电容反而变大。
- 稳定性可能变差。
- PVT 鲁棒性可能变差。
- 版图生成更困难。

因此，更合理的目标不是“所有前仿性能尽可能高”，而是：

```text
满足目标
+ 留合理裕量
+ 控制功耗、面积、寄生和稳定性风险
```

这可以发展成一个论文点：寄生感知的设计裕量分配。也就是根据不同节点和指标的寄生风险，动态决定哪些指标需要多留余量，哪些代价不能乱涨。

## 4. 寄生参数提取到底指导什么

寄生参数可以理解成版图实现后额外产生的“负担”。最直观的是寄生电容。

如果某个节点寄生电容变大，信号变化时要先给这个额外电容充放电，结果可能导致：

- 信号变慢。
- 带宽下降。
- 延迟增大。
- 相位裕度变差。
- 后仿性能比前仿差。

寄生参数提取的作用不是只报告一个总数，而是把后端物理影响变成可诊断信息。

例如：

```json
{
  "critical_net": "OUT",
  "problem": "输出节点寄生电容偏大",
  "possible_effect": "带宽下降、相位裕度变差",
  "suggest_backend": "缩短输出走线，调整布局布线",
  "suggest_frontend": "提高输出级驱动能力，重新 sizing"
}
```

这类结构化信息可以给 Harness 判断：问题应该回前端，还是回后端。

## 5. A/B/C/D 四类回退路线

### A. 偏置点漂移 / 功耗异常

现象：

- 后仿电流明显变大。
- 功耗明显升高。
- 节点电压偏离前仿。
- 器件工作区发生变化。

可能原因：

- 前端偏置设置太激进。
- 晶体管尺寸比例不合理。
- 前端设计余量不足。
- 寄生影响了偏置节点，使工作点漂移。

优先回退：

```text
参数优化 / sizing / bias 调整
```

这条路线主要依赖工作点一致性分析。

### B. 关键网络寄生过大

现象：

- 某些关键节点的寄生电容明显偏大。
- 输出节点、补偿节点、高阻节点等 critical net 负担过重。
- 后仿带宽下降或相位裕度变差。

可能原因：

- 关键线过长。
- 器件摆放太远。
- 走线绕路。
- pin 位置不合理。
- 关键节点金属面积过大。

优先回退：

```text
MAGICAL 候选版图生成 / 版图约束 / 布局布线
```

这条路线是寄生参数提取最直接支撑的方向。

### C. 多指 nf / 匹配 / 对称异常

现象：

- 前端网表中设置了 `nf=2`，但版图没有正确实现多指结构。
- 匹配器件没有对称摆放。
- 差分对两边寄生明显不一致。
- 电流镜两支路结构不一致。

可能原因：

- 器件映射规则不对。
- nf 展开方式不对。
- matching 或 symmetry 约束没有进入后端。
- 后端生成的器件结构不符合模拟版图语义。

优先回退：

```text
器件映射 / nf 展开规则 / matching 约束 / symmetry 约束
```

这条路线和 `AncstrGNN_benchmark` 这类约束提取工作有关。

### D. 系统性后仿性能退化

现象：

- 多个设计候选都出现明显后仿退化。
- 单纯改某条线或某个版图约束效果有限。
- 前端优化器总是选出“前仿好、后仿崩”的参数。

这时应该引入寄生感知前端模型。

它不是替代 PEX，也不是替代 MAGICAL，而是在真正跑后端前，给前端优化器一个寄生风险估计。

可以从简单到复杂分三层：

1. 规则模型：关键节点、高阻节点、输出节点等提前加风险惩罚。
2. 统计模型：用已有 MAGICAL case 学习参数、拓扑和寄生之间的关系。
3. GNN 模型：类似 ParaGraph，从电路图结构预测 layout parasitics。

## 6. 前端冻结与闭环优化

传统流程里，进入后端后前端通常会冻结。但在自动化闭环系统中，更准确的说法是：

```text
某一次候选设计进入后端时临时冻结；
如果后仿证明候选不满足约束，Harness 可以宣布该候选失败；
然后重新打开前端或后端进行修正。
```

所以不是所有后仿问题都回前端，也不是所有后仿问题都回后端。

正确逻辑是：

```text
后仿退化
-> Harness 失败归因
-> 如果是版图实现问题，回后端
-> 如果是前端设计对寄生太敏感，回前端
```

```text
寄生参数提取与前后端反馈建模
```

更具体地说：

```text

```

这个方向的价值在于：把后端看不见的寄生影响，翻译成前端、后端和 Harness 都能使用的诊断信号。
